# Aether Cards 应用开发记录 — 2026-05-10 (Part C)

## 本次开发概览

本次为 Aether Cards 应用进行了 v3→v5 的大规模迭代，涵盖对话框、手绘板、富文本编辑、LLM 流式渲染、思维链、Markdown/LaTeX 渲染、SQLite 多工作板存储等功能。

---

## 一、v3 新增功能

### 1. 对话框功能
- **工具栏**新增"对话"按钮
- **新对话状态**：输入框居中画布下方，支持切换模型、上传文件
- **持续对话状态**：发送消息后输入框移至右侧，对话展示UI从右侧浮入
- 支持新建对话、查看历史对话（最大高度70vh）
- AI回复支持"新卡片"和"添加到选中卡片"操作
- 模型调用通过 `os.llm.chat()` 统一接口（内联模式）
- 多模态消息支持（图片附件）
- 对话历史持久化：`GET/PUT /api/aether-cards/chat-history`

### 2. 手绘板功能
- **工具栏**新增"手绘板"按钮
- 独立应用 `drawboard.js`，2:3比例画画布窗口
- 支持画笔、橡皮擦、颜色选择、画笔粗细调整
- 支持撤销（Ctrl+Z）、清空
- 三种导出方式：到卡片、新建卡片、到对话
- 支持多个手绘板窗口同时打开

## 二、v4 布局重构与渲染升级

### 1. 详情视图布局重构
- **左 2/3 + 右 1/3** 布局（原 75%/25%）
- 左侧：上方 90% 富文本编辑器（contentEditable + 格式工具栏），下方 10% 图片条
- 右侧：LLM 对话区（全高）
- 格式工具栏：加粗、斜体、删除线、H2/H3/P、列表、引用、链接、清除格式
- HTML↔Markdown 双向转换：`htmlToMarkdown()` / `markdownToHtml()`
- 卡片内容存储为 Markdown，编辑器显示为 HTML

### 2. 流式渲染修复
- 旧：`innerHTML +=` 每次重新解析全部内容
- 新：`_streamRawText` 累积缓冲区，每次 `onText` 追加后整体 `fmtChat()`
- 智能滚动：`smartScroll(el)` 只在用户已在底部时自动滚动，不影响手动浏览

### 3. 思维链渲染（v4 → v5 迭代）
- **后端**：`llm/service.py` 的 `_stream_anthropic` 改用 `queue.Queue` 实现真流式，支持 `thinking_delta` 事件；`_stream_openai` 支持 `reasoning_content` 字段
- **前端 LLM 客户端**：`llm.js` 新增 `onThinking` 回调
- **v5 思维链 UI**：
  - `Thinking >` 标签 + 从左到右高亮扫描动画（`thinking-scan` keyframe）
  - 点击标签展开/折叠思维链内容
  - 流式结束后添加 `.done` 类停止扫描动画
  - 轻量设计：左侧 2px 边线 + 斜体 + 0.7 透明度

### 4. Markdown / LaTeX 渲染
- 动态加载 marked.js + KaTeX（CDN）：`loadRenderLibs()`
- `fmtChat()` 先处理 LaTeX（`$$...$$` 块级，`$...$` 行内），再处理 Markdown
- fallback：无 marked.js 时使用简单的代码块/行内代码/换行处理

### 5. 卡片预览富文本
- 画布上的卡片预览使用 `markdownToHtml()` 渲染（原 `esc()` 纯文本）
- 预览截取从 200 → 500 字符
- `.card-body` CSS 新增 h2/h3/p/strong/em/code/ul/ol 样式

### 6. 对话持久化
- `cardChatMap`：`{ cardId: conversationId }` 映射
- `restoreCardChat(cardId)`：打开详情/窗口化编辑时恢复 chatHistory
- `saveCardChat(cardId)`：`finalizeChat()` 末尾自动调用，每条消息发送后立即持久化
- 思维链内容随消息一并存储（`{ role, content, thinking }`）

### 7. 窗口化卡片 LLM 面板修复
- **层级修复**：面板添加到 `#window-stack`（与窗口同一 stacking context），z-index 通过 MutationObserver 与窗口同步
- **新增按钮**："加入卡片"、"加入对话"
- **历史恢复**：打开面板时渲染已有对话历史

### 8. 常规编辑界面按钮修复
- `renderChatMessages()` 为 assistant 消息添加操作按钮（`addChatActionButtons()`）
- 返回画布再进入卡片编辑，按钮和对话均保留

## 三、v5 多工作板与存储迁移

### 1. SQLite 存储
- 复用通用 `/api/db/cards/query|execute` API，不修改 server.py
- 数据库文件：`~/.aetheros/data/cards.db`
- 表结构：`boards`、`cards`、`conversations`、`messages`、`card_chat_map`
- 自动从旧 JSON 迁移：`migrateFromJSON()` 检测旧 `cards.json` + `chat_history.json`
- DB 不可用时 fallback 到 JSON API（`_dbAvailable` 标志）

### 2. 多工作板管理
- 工具栏新增"管理工作板"按钮，显示当前板名
- 管理面板：列表（名称、卡片数、创建时间）、新建、重命名、删除、切换
- 每个工作板独立存储卡片和对话
- `switchBoard()`：保存当前板 → 切换 → 加载新板 → 重置画布

### 3. 等待动画
- 三弹跳点动画（`.cards-thinking-dots`），带延迟，符合 cyberpunk 主题
- 发送消息后立即显示，首次 `onText`/`onThinking` 回调时被 `fmtChat()` 覆盖

## 五、Bug 修复记录

| 问题 | 根因 | 修复 |
|------|------|------|
| 流式传输失效 | `_do_stream()` 批量收集事件后返回 | 改用 `queue.Queue` 实时传递 |
| 窗口化面板层级错误 | 面板在 `document.body`，窗口在 `#window-stack`，不同 stacking context | 面板添加到 `#window-stack`，z-index MutationObserver 同步 |
| 对话不持久 | `saveCardChat` 仅在关闭详情时调用 | `finalizeChat()` 末尾自动调用 `saveCardChat` |
| 文本换行 | "LLM 对话" span 无 nowrap | 添加 `white-space:nowrap;flex-shrink:0` |
| 初始化崩溃 | `updateBoardName()` 无 try-catch，DB 失败时阻断整个初始化 | 加 try-catch + `Promise.allSettled` + 整体 try-catch |
| 错误消息不可见 | `appendChatErrorFloat` 追加到 `display:none` 的容器 | 改为输入框上方临时 toast（3秒自动消失） |
| smartScroll 无限递归 | 批量替换误伤函数内部的 `el.scrollTop = el.scrollHeight` | 修正为 `if (atBottom) el.scrollTop = el.scrollHeight` |
| 卡片预览纯文本 | `esc(preview)` 不渲染 Markdown | 改为 `markdownToHtml(preview)` |
